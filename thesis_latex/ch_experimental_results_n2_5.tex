\subsection{Eyeriss: Activation Register Sizing (CS2, CS3)}
\label{sec:eyeriss-cs2-cs3}

\subsubsection{Motivation}

Besides the weight register examined in CS1, every PE in the
Eyeriss-Like architecture contains three additional local storage
structures: an \emph{input register} (InReg), which buffers the
first layer's input activations; an \emph{intermediate register}
(IntReg), which buffers the activation values exchanged between
consecutive fused layers; and an \emph{output register} (OutReg),
which holds the final-layer output before it is written back to the
GlobalBuffer.

Of these three, only IntReg is genuinely affected by fusion.
The InReg sees exclusively the network's input, regardless of how
many layers are fused: intermediate activations produced inside the
fusion chain never pass through InReg, they are routed to IntReg
instead.
The InReg footprint is therefore identical to the single-layer case
and does not require a dedicated sweep.
Similarly, the OutReg stores only the last fused layer's output
channel residual, so its footprint does not grow with the number of
fused layers.

Under full fusion the IntReg must accommodate the residual channel
factors of \emph{all} intermediate activations, i.e.\ the $Z_i$
values that the spatial-array columns (SACols) cannot absorb.
The footprint therefore scales with the number of fused layers and
with the width of their channel dimensions.

The designer's question mirrors CS1:
\emph{given a PE budget, what is the minimum IntReg (or OutReg) that
admits a feasible fused mapping?}
CS2 answers this for the intermediate register and CS3 for the output
register.
In both sweeps all other registers (WReg, InReg, and OutReg or IntReg,
respectively) are held at generous values so that only the register
under test is the binding constraint.

\subsubsection{CS2 — Intermediate Register}
\label{sec:eyeriss-cs2}

\paragraph{Weight-dominant workloads (VGG16, ResNet18).}

size, the minimum-PE configuration that yields a feasible mapping.

    \midrule

    \midrule

    \bottomrule

\end{table}

The table reveals the same doubling rule observed for WReg in CS1.
The mechanism is as follows: the per-PE intermediate footprint equals
the total residual channel sum across all fused layer boundaries,
divided by the number of PE columns.
A smaller IntReg budget therefore forces the mapper to increase the
column count so that each PE's share of the footprint stays within
the register capacity.

Taking ResNet18 as an example, the total intermediate footprint
across 16~layer boundaries is approximately 209~entries when mapped
onto 16~columns.
At IntReg\,=\,400 this footprint fits comfortably, so the mapper
saturates at $256 \times 16 = 4{,}096$~PEs: enlarging IntReg beyond
400 no longer reduces the PE count.
Halving the register to IntReg\,=\,200 forces the mapper to double
the column count to 32, yielding $256 \times 32 = 8{,}192$~PEs,
because each PE must now hold its share within a tighter budget.
At IntReg\,=\,50 the array widens further to
$128 \times 128 = 16{,}384$~PEs.
Each halving of IntReg therefore roughly doubles the required column
count, driving a proportional increase in total PEs.

VGG16 follows the same pattern.
At IntReg\,=\,230 the mapper saturates at
$256 \times 16 = 4{,}096$~PEs, corresponding to a per-PE footprint
of $\sim$229~entries on 16~columns.
Reducing IntReg to 100 doubles the array to
$256 \times 32 = 8{,}192$~PEs, and at IntReg\,=\,50 it reaches
$512 \times 32 = 16{,}384$~PEs.

Figure~\ref{fig:eyeriss-cs2-inv} presents the designer-oriented
view: the horizontal axis is the PE budget and the vertical axis is
the minimum IntReg that makes the fused mapping feasible.
Reading the curve from left to right, one can directly read off the
register size that a given area constraint demands.
The slope is consistent with the doubling rule: every $2\times$
reduction in PE budget roughly doubles the minimum IntReg.

  \caption{Eyeriss CS2 — Minimum IntReg required as a function of PE

Figure~\ref{fig:eyeriss-cs2cs3} (top row) shows the energy measured
at the minimum-PE configuration for each IntReg size.
Energy increases monotonically with IntReg, because a larger register
incurs a higher access cost on every read.
For ResNet18 the increase is $1.4\times$ from IntReg\,=\,50 to
IntReg\,=\,1\,000 ($1.14 \times 10^{5} \to 1.59 \times 10^{5}$\,
$\mu$J), a modest penalty compared to the $2.4\times$ energy span
caused by WReg in CS1.

\paragraph{Activation-dominant workloads (FSRCNN, MC-CNN).}
For these workloads the intermediate register is not the binding
constraint.
FSRCNN achieves the same minimum PE configuration
($128 \times 4 = 512$~PEs) at every tested IntReg from 200 to 400;
energy scales linearly with register size but the PE count is
unaffected.
MC-CNN shows a marginal effect: at IntReg\,=\,15 the mapper requires
more PEs than at IntReg\,$\ge$\,30, where the PE count saturates.
In both cases the intermediate footprint is small because these
networks have few fused layers and narrow channels.

\subsubsection{CS3 — Output Register}
\label{sec:eyeriss-cs3}

The output register stores only the last fused layer's channel
residual, so its footprint is inherently smaller than that of IntReg
or WReg.
The original single-layer Eyeriss design uses OutReg\,=\,16 entries,
and this value turns out to be sufficient for full fusion as well at
the PE budgets that WReg and IntReg already demand.

Table~\ref{tab:eyeriss-cs3-outreg} confirms this.
For ResNet18, OutReg\,=\,16 requires $256 \times 32 = 8{,}192$~PEs,
while the WReg constraint (CS1) already forces 16\,384~PEs at the
tightest feasible point.
OutReg is therefore automatically satisfied whenever WReg is.
Saturation occurs at OutReg\,=\,32 ($256 \times 16 = 4{,}096$~PEs).
VGG16 tells the same story: OutReg\,=\,16 fits at
$128 \times 32 = 4{,}096$~PEs, which is also the saturation point.

has no effect on the PE count whatsoever: all tested OutReg sizes yield
the same minimum configuration.

\subsubsection{Combined Energy View}

Figure~\ref{fig:eyeriss-cs2cs3} collects the energy behaviour of all
four workloads for both register sweeps.
The top row (CS2, IntReg) and the bottom row (CS3, OutReg) share a
common pattern: energy rises with register size because larger SRAM
structures cost more per access.
For weight-dominant workloads the effect is modest ($< 1.4\times$
over the tested range), while for FSRCNN the linear energy growth
is steeper in relative terms because FSRCNN's small absolute energy
makes each additional register entry more visible.

\paragraph{Key takeaway.}
The intermediate register follows the same PE-doubling-per-halving
rule as the weight register, but its absolute footprint is roughly
one order of magnitude smaller, so it becomes binding only at PE
counts well below the WReg minimum.
The output register is even less constraining: with OutReg\,=\,16
(the value used in the original single-layer Eyeriss), the fused
mapping is already feasible at the PE budgets imposed by WReg.
The input register is unaffected by fusion altogether, because it
handles only the first layer's input and its footprint remains the
same as in single-layer execution.
In practice, the binding hierarchy for the Eyeriss-Like architecture
under full fusion is
$\text{WReg} \gg \text{IntReg} > \text{OutReg} \ge \text{InReg}$.
